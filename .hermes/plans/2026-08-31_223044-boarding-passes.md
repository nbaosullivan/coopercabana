# Boarding Pass Delivery — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Let each attendee see and open their own boarding pass from the Flights tab, with the pass images dropped into the repo by the organiser and named by attendee UUID — served only to the signed-in owner (or an admin), never publicly fetchable.

**Architecture:** Boarding pass images live in `boarding/<attendee-uuid>-outbound.png` / `-return.png` at the **repo root (outside `public/`, so the CDN never serves them directly)**. A route handler `app/boarding/[file]/route.ts` streams them after verifying the session cookie is the pass owner or an admin (404 otherwise). The Flights tab renders only the signed-in user's passes, hiding missing files via `<img onError>` fallthrough — no DB or schema changes. The service worker's existing network-first caching makes the pass available offline at the airport after it's been viewed once.

**Tech Stack:** Next.js 14 (App Router), TypeScript, Tailwind, React client component, `fs` in a route handler, `outputFileTracingIncludes` in next.config for serverless bundling, existing `lib/` vitest setup.

---

## Context & Assumptions

- **Auth:** shared group password (`coops`) → `stag_user_id` HTTP-only cookie (httpOnly, sameSite lax, path `/`) → `UserProvider` exposes the signed-in `PublicAttendee` (with `id` = UUID) via `useUser()`. Same-origin `<img>` requests carry the cookie automatically, so a route handler can auth the image stream with `getSessionAttendeeId()`.
- **Flights tab:** `app/flights/page.tsx` (server) renders `components/FlightsView.tsx` (client, has `useUser()`), then `TaxiClusters`. The current user's own pass belongs in `FlightsView`, below the "My flights" form.
- **Pass ownership:** boarding passes contain names/PNRs/barcodes → each person sees **only their own**. Admin (`is_admin = true`, Nick) may view any pass (matches admin unlock powers elsewhere, and lets the organiser verify uploads).
- **Files arrive as images** (PNG/JPG/WEBP) — confirmed by user.
- **Per-leg images** — confirmed by user (`-outbound` / `-return`).
- **Gated behind login** — confirmed by user.
- **Repo privacy:** this assumes the GitHub repo is private. If it were public, boarding passes (PNRs) should NOT be committed to it — that would need a different storage plan.

## Storage & Serving Design

### Files on disk (committed to the repo)

```
boarding/                                    # repo root, NOT under public/
  11111111-1111-1111-1111-111111111111-outbound.png
  11111111-1111-1111-1111-111111111111-return.png
  33333333-3333-3333-3333-333333333333-outbound.jpg
  ...
```

Supported extensions (tried in order): `png`, `jpg`, `jpeg`, `webp`.
A bare `<uuid>.png` is still accepted as a single combined pass (shown once, in the outbound slot).

### Serving (gated route handler)

`app/boarding/[file]/route.ts`:
1. Validates `file` against a strict `<uuid>[-outbound|-return].<ext>` pattern (rejects path traversal / anything else → 404).
2. Parses the attendee UUID + leg from the filename.
3. Reads the session (`getSessionAttendeeId()`) and loads that attendee; allows the request only if the session user **is** the pass owner **or** is an admin. Anything else → 404 (do not reveal whether the file exists).
4. Reads `boarding/<file>` via `fs`, streams it with the right `Content-Type`, plus `Cache-Control: private, max-age=3600`.

### Serverless bundling (Netlify/Vercel)

Next.js route handlers that use `fs` only get those files deployed if they are included in the output trace. Add to `next.config.mjs`:

```js
experimental: {
  serverActions: { bodySizeLimit: '2mb' },
  outputFileTracingIncludes: {
    '/boarding/[file]': ['./boarding/**'],
  },
}
```

**Verification during implementation is mandatory:** after deploy, confirm a pass loads in production (see Task 7). If Netlify tracing still drops the folder, the documented fallback is a build-time script that reads `boarding/` and emits `lib/boardingPassData.ts` (uuid+leg → base64 data URL), imported by the route handler — zero `fs` at runtime, works on any host. See Open Questions.

### PWA / offline

The service worker (`public/sw.js`) network-first caches same-origin GET responses, including `/boarding/<file>`. After the owner views their pass once, it is cached and renders offline at the airport. **Do NOT** precache passes in the SW `SHELL` list: the gated route returns 404 to an unauthenticated install-time fetch, so precaching would cache nothing and would only burn bytes.

```ts
const EXTS = ['png', 'jpg', 'jpeg', 'webp'];

export type BoardingPassLeg = 'outbound' | 'return';

/**
 * Candidate URLs for an attendee's boarding pass image(s), most specific
 * first. Outbound falls back to a single combined pass (`<uuid>.<ext>`);
 * return does not, so a lone combined pass is shown exactly once.
 */
export function boardingPassCandidates(
  attendeeId: string,
  leg: BoardingPassLeg
): string[] {
  const base = `/boarding/${attendeeId}`;
  const prefixes = leg === 'outbound' ? [`-outbound`, ''] : [`-return`];
  return prefixes.flatMap((p) => EXTS.map((ext) => `${base}${p}.${ext}`));
}
```

### Task 3: Gated route handler `app/boarding/[file]/route.ts`

**Objective:** Serve a pass image only to its owner or an admin; 404 for everyone else, without revealing whether the file exists.

**Files:**
- Create: `app/boarding/[file]/route.ts`

**Route handler:**

```ts
import { NextRequest, NextResponse } from 'next/server';
import fs from 'node:fs/promises';
import path from 'node:path';
import { getSessionAttendeeId } from '@/lib/session';
import { getAttendeeById } from '@/lib/db';

const UUID_RE =
  /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;
const FILE_RE = /^([0-9a-f-]+)(?:-(outbound|return))?\.(png|jpg|jpeg|webp)$/i;
const EXT_TYPE: Record<string, string> = {
  png: 'image/png',
  jpg: 'image/jpeg',
  jpeg: 'image/jpeg',
  webp: 'image/webp',
};

export async function GET(
  _req: NextRequest,
  { params }: { params: { file: string } }
): Promise<NextResponse> {
  const { file } = params;

  const m = FILE_RE.exec(file);
  if (!m || !UUID_RE.test(m[1])) {
    return new NextResponse('Not found', { status: 404 });
  }
  const ownerId = m[1];

  // Auth: only the pass owner, or an admin, may view it.
  const sessionId = getSessionAttendeeId();
  if (!sessionId) return new NextResponse('Not found', { status: 404 });
  const me = await getAttendeeById(sessionId);
  if (!me) return new NextResponse('Not found', { status: 404 });
  if (me.id !== ownerId && !me.is_admin) {
    return new NextResponse('Not found', { status: 404 });
  }

  const safeName = path.basename(file); // belt-and-braces after FILE_RE
  const filePath = path.join(process.cwd(), 'boarding', safeName);
  let bytes: Buffer;
  try {
    bytes = await fs.readFile(filePath);
  } catch {
    return new NextResponse('Not found', { status: 404 });
  }

  const ext = m[3].toLowerCase();
  return new NextResponse(bytes, {
    status: 200,
    headers: {
      'Content-Type': EXT_TYPE[ext] ?? 'application/octet-stream',
      'Cache-Control': 'private, max-age=3600',
    },
  });
}
```

**Notes:**
- `FILE_RE` group 1 is the full uuid-ish token (`[0-9a-f-]+`), then `UUID_RE` enforces the real shape — path traversal (`..`) and slashes never pass.
- Uses the existing `getSessionAttendeeId()` / `getAttendeeById()` from `lib/session.ts` and `lib/db.ts` — no new auth machinery. Both work in mock and Supabase mode.
- **Fix `params` typing if lint objects:** with Next 14 the generated types prefer `params: Promise<{ file: string }>`; align to whatever `next lint`/`tsc` expects (task step verifies).

### Task 5: Build `components/BoardingPassCard.tsx`

**Objective:** A self-contained client component that renders the current user's outbound/return pass slots with onError fallthrough and a full-screen lightbox.

**Files:**
- Create: `components/BoardingPassCard.tsx`

**Complete component:**

```tsx
'use client';

import { useState } from 'react';
import { Ticket, X, Download } from 'lucide-react';
import { boardingPassCandidates } from '@/lib/boardingPass';

function usePassSlot(candidates: string[]) {
  const [src, setSrc] = useState<string | null>(candidates[0] ?? null);
  function onError() {
    if (!src) return;
    const i = candidates.indexOf(src);
    if (i >= 0 && i < candidates.length - 1) setSrc(candidates[i + 1]);
    else setSrc(null);
  }
  return { src, onError };
}

function PassImage({
  src,
  label,
  onOpen,
}: {
  src: string;
  label: string;
  onOpen: (src: string) => void;
}) {
  return (
    <button
      type="button"
      onClick={() => onOpen(src)}
      className="block w-full overflow-hidden rounded-xl border border-zinc-800 bg-white"
      aria-label={`Open ${label} boarding pass full screen`}
    >
      {/* eslint-disable-next-line @next/next/no-img-element */}
      <img src={src} alt={label} className="max-h-56 w-full object-contain" />
    </button>
  );
}

export default function BoardingPassCard({ attendeeId }: { attendeeId: string }) {
  const outbound = usePassSlot(boardingPassCandidates(attendeeId, 'outbound'));
  const ret = usePassSlot(boardingPassCandidates(attendeeId, 'return'));
  const [fullscreen, setFullscreen] = useState<string | null>(null);

  const hasPass = Boolean(outbound.src || ret.src);
  if (!hasPass) return null;

  return (
    <div className="rounded-2xl border border-zinc-800 bg-zinc-900 p-5">
      <div className="mb-3 flex items-center gap-2">
        <Ticket className="h-4 w-4 text-emerald-500" />
        <h2 className="text-sm font-semibold text-zinc-200">Boarding passes</h2>
      </div>

      <div className="grid grid-cols-1 gap-3">
        {outbound.src && (
          <div>
            <p className="mb-1.5 text-xs font-medium uppercase tracking-wide text-zinc-500">
              Outbound
            </p>
            <PassImage src={outbound.src} label="Outbound boarding pass" onOpen={setFullscreen} />
          </div>
        )}
        {ret.src && (
          <div>
            <p className="mb-1.5 text-xs font-medium uppercase tracking-wide text-zinc-500">
              Return
            </p>
            <PassImage src={ret.src} label="Return boarding pass" onOpen={setFullscreen} />
          </div>
        )}
      </div>

      {fullscreen && (
        <div
          className="fixed inset-0 z-50 flex flex-col items-center justify-center bg-black/95 p-4"
          onClick={() => setFullscreen(null)}
          role="dialog"
          aria-modal="true"
        >
          {/* eslint-disable-next-line @next/next/no-img-element */}
          <img
            src={fullscreen}
            alt="Boarding pass"
            className="max-h-[85vh] max-w-full rounded-lg bg-white object-contain"
          />
          <div className="mt-4 flex gap-3">
            <a
              href={fullscreen}
              download
              onClick={(e) => e.stopPropagation()}
              className="flex items-center gap-1.5 rounded-xl bg-emerald-500 px-4 py-2 text-sm font-semibold text-cream"
            >
              <Download className="h-4 w-4" /> Save
            </a>
            <button
              type="button"
              onClick={(e) => {
                e.stopPropagation();
                setFullscreen(null);
              }}
              className="flex items-center gap-1.5 rounded-xl border border-zinc-700 px-4 py-2 text-sm font-semibold text-zinc-200"
            >
              <X className="h-4 w-4" /> Close
            </button>
          </div>
        </div>
      )}
    </div>
  );
}
```

**Note:** the single combined pass (`<uuid>.png`) renders in the outbound slot labelled "Outbound" — acceptable v1; refine copy if it bothers you.

## Risks, Tradeoffs & Open Questions

- **Serverless `fs` reliability.** The one real risk: does Netlify's opennextjs bundle the `boarding/` folder for the route handler? `outputFileTracingIncludes` is the documented mechanism; Task 7 verifies it in production. **Fallback if it fails:** a tiny build script (`scripts/inline-boarding-passes.mjs`, run via `prebuild`) that reads `boarding/` and writes `lib/boardingPassData.ts` exporting `{ '<uuid>-outbound.png': 'data:image/png;base64,...' }`; the route handler imports it instead of `fs`. Zero runtime fs, works on any host. Cost: base64 blobs in a generated file (kept out of git via .gitignore, regenerated each build).
- **Mock mode nuance.** `getAttendeeById` reads mock state; the route handler works identically in mock and Supabase mode. No schema change needed.
- **Offline.** Gated passes are cached by the existing network-first SW after first view. Passes are NOT precached (unauthenticated install fetch would 404). If you later want guaranteed offline without prior view, that needs a login-aware precache — overkill for a stag weekend.
- **Repo privacy.** Boarding passes contain PNRs/barcodes. This plan assumes a **private** repo. If the repo ever goes public, the `boarding/` images must be removed (and the build-time-inline fallback pointed at a private source).
- **PDFs.** Confirmed out of scope — images only. PDFs would need `<iframe>`/`<object>` or download-only handling (iOS Safari won't inline-render PDFs well).
- **Admin view.** The route lets admin view any pass, but v1 has no UI for it (admin sees their own on the Flights tab). A follow-up could add a per-attendee "pass ✓" indicator in `FlightMatrix` for the organiser — deliberately out of scope.
- **Notifications** ("your pass is ready") would require push infra — out of scope; the pass simply appears on the Flights tab.
